# openwork

**이 스킬이 내놓는 것은 「열린 것」이 아니라 「열린 채로 적힌 것」이다.** 그 차이가 이 문서에서
제일 중요하고, 사용자에게도 그렇게 말해야 한다.

## 0단계 — 기록 폴더를 직접 읽지 않는다

세 기록 폴더는 **4.36MB(약 145만 자, 파일 251개)** 다. `grep` 으로 훑거나 `INDEX.md` 를 열어
요약하려 들면 안 된다 — `.claude/wiki/plan_log/프로젝트-컨텍스트.md` 가 *"세 INDEX와 전체 로그를 기본
문맥으로 읽는 것"* 을 이미 기각했고, 세 `INDEX.md` 만 합쳐도 644KB 다.

수집은 스크립트가 한다.

```bash
python "<이 스킬 폴더>/../../scripts/openwork/collect.py"
```

기본 출력은 **묶음별로 접힌 JSON** 이다. 한 묶음의 뒷정리까지 보려면:

```bash
python "<이 스킬 폴더>/../../scripts/openwork/collect.py" --group 검색-생성
```

원문이 필요하면 `--raw`, 접지 않은 전체는 `--flat` 이다. **`--raw` 는 기본이 아니다** — 붙이면
출력이 100KB 를 넘어 「전부 읽는다」를 스크립트로 옮겨 놓은 꼴이 된다.

**stderr 의 경고를 반드시 읽고 사용자에게 옮긴다.** 경고는 구조가 어긋났다는 신호이고, 그때
목록은 실제보다 **짧다**. 조용히 짧아지는 것이 이 도구의 유일한 실패 모드다.

## 1단계 — 무엇을 받았는지 안다

| 칸 | 뜻 |
|---|---|
| `kind` | `decision` = `plan_log` 의 아직 안 정한 것 · `followup` = `task_log` 의 만들고 난 뒤 뒷정리 |
| `group` | 기능. `plan_log` 파일명이다. `null` 이면 어느 기능인지 못 붙인 것 |
| `group_basis` | `own`(제 파일) · `explicit`(파일을 직접 가리킴) · `name`(이름이 나옴) · `file`(그 세션 기록이 가리키는 기능) |
| `what` | **뭔지.** 불릿의 굵은 머리를 그대로 옮긴 것 |
| `why` / `why_basis` | **왜.** `quote` 면 원문 인용이고, `null` 이면 원문에 없다 |
| `round` · `date` | 그 항목이 적힌 회차와 날짜 |
| `refs` | 선행을 되짚을 근거 — `rounds` · `files` · `symbols` · `order_words` |

## 2단계 — 묶고 순서를 매긴다

**묶음은 이미 정해져 나온다**(`group`). 새로 분류하지 않는다.

**순서는 선행이다.** `refs` 를 근거로 「A 가 닫혀야 B」를 세우고, 표에 **근거를 함께 적는다.**

- `refs.files` · `refs.rounds` 가 다른 항목을 가리키면 그것이 선행 후보다
- `refs.order_words`(먼저·선행·있어야·전제·선결)가 있으면 `why` 나 `raw` 에서 무엇이 먼저인지
  읽어낸다
- **근거가 없으면 추론이라고 표시한다.** 실측으로 `## 미결` 232건 중 75%만 이런 근거를 갖고
  있다. 나머지 25%를 확신처럼 적으면 표가 없는 사실을 말한다

묶음 순서는 **미결이 많고 선행이 적은 것부터**다 — 지금 손댈 수 있는 것이 위로 온다.

## 3단계 — 표를 그린다

| 순서 | 무엇 | 왜 / 무엇이 있어야 | 선행 | 출처 |
|---|---|---|---|---|
| 1 | `what` | `why` (인용) 또는 요약 | 있으면 항목 번호 + 근거 | `source` · `N회차` · 날짜 |

규칙 넷.

1. **`why` 가 `quote` 면 그대로 옮긴다.** 다듬지 않는다 — 인용이 이 표에서 유일하게 호출마다
   같은 칸이다
2. **`why` 가 `null` 이면 `raw` 를 읽어 한 줄로 줄이고 「요약」이라고 표시한다.** 실측으로
   `## 미결` 은 60%가 인용을 갖지만 `## 7. 남은 것` 은 **1%** 다. 표시를 빼면 표의 절반이
   호출마다 달라지는데 읽는 사람은 그걸 모른다
3. **`followup` 은 접어 둔다.** 묶음마다 「뒷정리 N건」으로 적고, 사용자가 물으면 그때
   `--group` 으로 펼친다
4. **모든 행에 출처·회차·날짜를 단다.** 이게 사용자가 「이거 이미 끝난 거 아냐?」를 되짚는
   유일한 손잡이다

## 4단계 — 무엇을 못 보는지 함께 말한다

한 번은 반드시 말한다. 표만 주고 끝내면 사용자가 이걸 완결된 할 일 목록으로 읽는다.

- **닫힌 것이 섞여 있을 수 있다.** 취소선(`~~`)이 달린 것은 빠지지만(실측 `## 미결` 232건 중
  72건 = 31%), **다른 파일의 회차가 닫은 것은 안 빠진다.** `.claude/wiki/plan_log/frontend.md` 의 *"배선은
  여전히 미결"* 이 `backend/app/templates/_answer.html` 에서 이미 닫힌 채 서 있었다.
  그 비율은 **아직 아무도 안 쟀다**
- **`group` 이 `null` 인 뒷정리가 많다.** `task_log` 는 파일이 기능이 아니라 세션이라
  기능이 본문 링크에만 남는다
- **깨진 테스트·미커밋 변경은 재료가 아니다.** 이 표는 *기록에 적힌 것*만 본다
- **지금 이 순간의 사진이다.** 같은 트리에 다른 세션이 붙어 있으면 부를 때마다 수가 다르다
  (실측: 한 논의 중에 `## 미결` 이 226 → 232 로 움직였다). `generated_at` 을 함께 낸다

## 이 스킬의 범위

**모아서 보여주기만 한다.** 항목을 닫거나 `plan_log`·`task_log` 를 고치지 않는다 — 무엇을
만들지 정하는 것은 `plan-log`, 만들고 난 뒤 기록하는 것은 `task-log` 다. 사용자가 표를 보고
"이거 하자"라고 하면 그 기능의 `.claude/wiki/plan_log/<기능>.md` 를 열고 해당 스킬로 넘긴다.
