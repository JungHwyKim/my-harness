# verify-log

이 저장소의 판단은 전부 실측에서 나왔다. 그런데 **그 수치가 사는 집이 없다.**

`regression/baseline.json` 은 승인된 기대값 **하나**라 회차가 안 쌓이고, `.claude/wiki/task_log/` 3절은
회고 산문과 섞여 회차 간 비교가 사람 눈이고, Stop 훅이 돌린 전체 pytest 결과는 **아무 데도
안 남는다**(성공하면 출력조차 없다). 구멍은 실제로 뚫려 있다 — `vision_calls` ·
`llamaparse_calls` 는 스키마에도 있고 `document-ingestion` 이 적으라고 지시하는데
`.claude/wiki/task_log/` 어디에도 값이 **한 번도** 들어간 적이 없다. 담을 칸이 없었기 때문이다.

이 스킬이 그 칸이다.

## 0단계 — 두 데이터가 답하는 질문이 다르다

이걸 안 가르면 "테스트 2종"은 그냥 분류표가 되고, 이 기록은 수치를 옮겨 적는 노동이 된다.

| 데이터 종류 | 답하는 질문 | 못 답하는 질문 | 저장소에 남나 |
|---|---|---|---|
| **가상 데이터** | 규칙이 도는가. 경계에서 어떻게 되는가 | **이 규칙이 필요한가. 임계값이 얼마인가** | 안 남는다 — **생성 코드**로 재현한다 |
| **실제 데이터** | 이 규칙이 실제로 필요한가. 값은 얼마인가 | 실파일에 없는 입력에서 어떻게 되는가 | 안 남는다 — `tests/fixtures/` 는 gitignore |

- **가상 수치로 임계값을 정하지 않는다.** 합성 문서는 만든 사람이 기대한 모양을 그대로 갖고
  있어서 **자기 확인**이 된다. 이 저장소의 임계값은 전부 실파일에서 나왔고, 지시서 초안을
  뒤집은 것도 실측이었다
- **실파일이 못 만드는 입력은 가상이 만든다.** 경계값·극단·0건은 실파일에 *우연히* 있어야만
  검증되고 그 우연은 문서를 바꾸면 사라진다. 지금 그 자리가 비어 있다 —
  `tests/ingestion/splitter/test_splitter_real.py` 의
  `test_split_table_pieces_keep_header` 는 `if not by_source: pytest.skip(...)` 으로,
  그 문서에 '쪼개진 표'가 없으면 스스로 건너뛴다
- **둘을 한 문장에 섞지 않는다.** 가상에서 통과한 것을 실측처럼 적으면, 다음 사람은 이 규칙이
  실제 문서에서 검증됐다고 믿는다

## 1단계 — 무엇을 확인할지 정하고, 비용부터 본다

**순서가 중요하다. 돌리기 전에 돈이 나가는지부터 본다.**

실행 방식과 비용은 `document-ingestion` 1단계의 A/B/C 표가 답한다. **여기 복제하지 않는다.**
기본은 A(`detect_regions()` 단독, 과금 없음)이고, 유료 경로(C)는 무엇을 위해 얼마나
호출하는지 밝히고 승인을 받는다. `-m integration` 은 어느 경우에도 자동으로 안 돌린다.

확인하려는 것을 한 문장으로 적는다. **"규칙이 도는가"인지 "임계값이 맞는가"인지 가른다** —
전자는 가상으로 되고 후자는 실파일이 있어야 한다. 이 구분이 2·3절 중 어디에 힘을 줄지를 정한다.

**유료 경로를 돌릴 거면 여기서 라벨을 정한다.** `COST_LABEL=<이 회차 이름>` 을 주고 돌리면
비용 로그가 그 이름으로 호출을 한 줄씩 쌓고, 회고 때 그 표를 낸다. **손으로 세지 않는다** —
지금까지 `- 비용: 생성 LLM 2회` 처럼 **횟수만** 적힌 줄이 남은 이유가 셀 것이 없어서였다.

**표를 내는 명령은 프로젝트가 정한다** — `.claude/harness.json` 의 `cost_report_command` 다
(agentic-rag-proj 에서는 `python -m cost.report --label <이름>` 이다). **그 키가 없으면 이
절을 통째로 건너뛴다** — 비용 로그를 안 두는 저장소가 있고, 없는 명령을 돌리면 나오는 것은
「비용 0」이 아니라 오류인데 그 오류가 「돈을 안 썼다」로 읽히기 쉽다.

그 표에서 **회계 줄을 지표보다 먼저 읽는다.** 폴백이 0이 아니면 그 회차의 품질 수치를
먼저 의심한다 — Cohere 한도 초과 30건이 품질 저하로 읽힌 전례가 있다
(`.claude/wiki/verify_log/2026-08-27-리랭커-cohere.md`). **금액은 `cost/pricing.py:CHECKED_ON` 이
`None` 인 동안 옮겨 적지 않는다**(사람이 단가를 확인한 날짜가 없다는 뜻이다).
호출 수와 토큰은 관측이라 그대로 써도 된다.

## 2단계 — 가상 데이터

### 만드는 법

**생성 방식은 `tests/conftest.py` 것을 쓴다. 새 방식을 발명하지 않는다.** 거기 이미 포맷별
함정이 주석과 함께 박혀 있다 — PDF 는 `_write_korean()` 으로 TTF 를 임베드해야 하고(내장
CJK 폰트로 쓰면 글자는 보이는데 추출이 안 돼 스캔본으로 오인된다), HWPX 는 `zipfile` 에
`mimetype` + `Contents/*.xml` 을 직접 조립한다.

**한 축만 바꾼 변종을 2~3개 만든다.** 경계 바로 아래 / 정확히 / 바로 위. 하나만 만들면
"우연히 통과"와 "규칙이 도는 것"을 못 가른다.

임시 스크립트는 **스크래치패드에 두고 저장소에 남기지 않는다.** 대신 **기록에 그대로
인라인한다** — 실파일과 달리 가상 데이터는 코드가 곧 입력이라, 코드를 남기면 완전히 재현된다.
이것이 가상 쪽의 유일한 재현 수단이다.

### 기대값을 먼저 적고 돌린다

**돌린 뒤에 기대값을 맞추면 아무것도 검증하지 않는다.** 실제로 그렇게 쓴 테스트가 있었다 —
splitter 작업의 `test_split_table_pieces_keep_header` 초판이 `rows[0] == chunk.metadata["rows"][0]`
으로 자기 자신을 비교하고 있었고, 통과해도 아무것도 보장하지 않았다.

그래서 표의 열 순서가 `입력 | 기대 | 실측 | 판정` 이다. 기대 칸을 비운 채 돌리지 않는다.

### 쓸 만한 것이 나오면 승격한다

같은 합성 입력을 두 번 이상 쓰게 되면 `tests/conftest.py` 픽스처로 올린다. 일회성 탐침까지
올리면 conftest 가 비대해지므로 **재발한 것만** 올린다.

## 3단계 — 실제 데이터

`tests/fixtures/` 는 gitignore 라 환경에 따라 없다. **없으면 조용히 skip 하고 "없어서 못
쟀다"를 7절에 적는다.** 없는 것을 회귀로 판정하지 않고, 안 돌린 것을 돌린 척하지 않는다.

세는 항목은 `document-ingestion` 2단계와 같다(형식을 여기 복제하지 않는다). 거기에 이
기록만의 항목 하나를 더한다.

### 파일 신원을 적는다 — 이름만으로는 문서를 못 가리킨다

입력이 저장소에 없으므로, 파일명만 적힌 수치는 다른 사람이 검증할 수 없다. **바이트 수와
sha256 앞 12자를 함께 적는다.**

이름만 믿다가 실제로 사고가 났다. `tests/ingestion/loader/document/test_hwpx_real.py` 의
`_find()` 가 "여러 개에 걸리면 `pytest.fail`" 로 짜여 있는 이유가 그것이다 — 파일명 조각
"시행령 개정안" 이 세로쪽 파일과 가로쪽 파일 두 개에 걸려, 한쪽에서 사람이 확인한 쪽 수 정답이
쪽 수가 다른 엉뚱한 문서에 적용될 뻔했다.

```powershell
.\.venv\Scripts\python.exe -X utf8 -c "import hashlib; from pathlib import Path; [print(f'{p.name}|{p.stat().st_size}|{hashlib.sha256(p.read_bytes()).hexdigest()[:12]}') for p in sorted(Path('tests/fixtures').glob('*'))]"
```

**`-X utf8` 을 빼지 말 것.** 뺴면 한국어 파일명이 콘솔 기본 인코딩(cp949)에서 `2025��
�б���Ϲ�` 처럼 깨져 나온다. 신원을 적으려고 돌리는 명령인데 이름이 깨지면 아무 소용이 없고,
예외가 안 나서 알아차리기도 어렵다. 이 저장소가 `_hookutil.read_payload()` 에서 겪은 것과
같은 종류의 함정이다.

### 대조 없는 수치는 판정이 아니다

혼자 있는 숫자는 아무것도 말하지 않는다. `regression/baseline.json` 또는 사람이 확인한
정답과 대조한다. 기준선이 없으면 `regression-test` 스킬로 먼저 만든다.
**달라진 항목만** 적는다 — 안 바뀐 것을 나열하면 바뀐 것이 묻힌다.

## 4단계 — 테스트 스위트

```powershell
.\.venv\Scripts\python.exe -m ruff check .
.\.venv\Scripts\python.exe -m pytest -q
```

**기억이나 대화 위쪽의 값을 옮겨 적지 않는다.** 그 사이 코드가 또 바뀌었을 수 있고, 기록에
틀린 숫자가 박히면 기록 전체를 못 믿게 된다. 둘 다 몇 초면 끝난다.

**skip 이 있으면 왜 skip 인지 적는다.** 픽스처가 없어서인지, 해당하는 입력이 그 문서에
없어서인지는 전혀 다른 얘기다. 없는 것을 통과로 위장하지 않는다.

## 5단계 — 기록하고 판정한다

경로는 `.claude/wiki/verify_log/YYYY-MM-DD-<주제>.md` 다. 검증 한 번에 파일 하나이고, `.claude/wiki/task_log/` 와
같은 주제를 다뤘으면 **파일명을 맞춰 둔다** — 짝이 눈에 보인다.

### 형식

- 비용: 외부 API 호출 없음  /  <`python -m cost.report --label <이 회차>` 표를 붙인다>

**없는 절은 `없음` 한 줄로 남기고 번호를 건너뛰지 않는다.** 회차 간 비교가 깨진다
(`task-log` 와 같은 규약).

본문 마크다운 규칙은 `.claude/wiki/plan_log/기록-형식.md` 가 정한 것을 따른다 — **원문에 열 이름이 이미
있는 블록만 표로 옮기고, 없으면 코드펜스에 그대로 둔다.** 열 이름을 지어내는 순간 옮기기가
아니라 해석이 된다.

**산문과 표 헤더 규칙도 같은 파일 3회차에 있다** — 영어 직역체 다섯(명사화 주어 · 은유 압축 ·
강조 관용구 되풀이 · 삽입절 3겹 · 뜻 없이 쓴 전문용어)을 막고, 낱말 `자[尺]`·`잣대`·`판` 을
쓰지 않고, 표 헤더 첫 칸에 `항목` 과 빈 칸을 쓰지 않는다.

### 판정은 셋이다

- **의도한 변화** — 이번 변경이 노린 것이고, 새 값이 맞다는 근거가 있다
- **회귀** — 나빠졌거나, 이번 변경과 무관한 곳이 움직였다
- **확인 필요** — 어느 쪽인지 못 정했다. **억지로 결론 내지 않는다**

가르는 법은 `regression-test` 3단계에 있다. 복제하지 않는다.

## 6단계 — INDEX 갱신하고 넘긴다

`.claude/wiki/verify_log/INDEX.md` 에 한 줄 추가한다(최신이 위). 링크 + 대표 수치 + 판정으로 끝낸다.

그 다음은 각자의 자리로 보낸다.

| 나온 것 | 어디로 |
|---|---|
| 의도한 변화로 판정한 수치 | `regression-test` — 기준선 갱신은 거기서만 |
| 회귀 · 고쳐야 할 버그 | `ingestion-specialist` (또는 사용자에게 보고) |
| 무엇을 왜 골랐나 · 되돌린 시도 | `task-log` — 3절 지표는 이 기록을 링크한다 |
| 설계가 안 정해져서 막힌 것 | `plan-log` |

## 언제 이 스킬이 아닌가

- 실파일을 **재고 원인을 확인하는 것** → `document-ingestion`
- 기준선과 **대조해 판정하는 것** → `regression-test`
- 코드가 **계약·규칙**을 지키는지 → `rag-code-review`
- **무엇을 왜 골랐나 · 무엇을 버렸나** → `task-log` (수치가 논증의 근거로 쓰이면 그쪽이다)
- 아직 안 만든 것의 방향 → `plan-log`

수치가 **측정값**이면 여기, **논증의 근거**면 `.claude/wiki/task_log/` 다. `pytest 337 passed` 는 여기고,
`큰 글씨와 마커가 겹치는 문단이 0/74 라 마커 승격을 기각했다` 는 저기다 — 뒤엣것은 떼어내면
문장이 죽는다.

## 이 스킬의 범위

**재고 남기는 것까지 한다. 코드를 고치지 않는다.** 고칠 것이 보이면 보고하고 넘긴다.

쓰기가 허용되는 것은 `.claude/wiki/verify_log/` 아래뿐이다. `regression/baseline.json` 은 **안 건드린다** —
갱신은 `regression-test` 의 판정을 거쳐야 한다.

`-m integration` 은 자동으로 돌리지 않는다. 유료 경로가 필요하면 비용을 밝히고 허락을 구한다.
