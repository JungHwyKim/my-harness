# Doctor 명령 구현 작업 명세

## 목적

이 저장소를 템플릿으로 시작하거나 파일을 다른 프로젝트에 복사한 직후, 훅과 품질 검사가 실제로 연결되어 있는지 수동으로 확인한다. 이 파일은 이번 작업의 인수인계 문서이며, 구현 후 삭제할 수 있다.

## 실행 계약

- 저장소 루트에서 `python .claude/harness/scripts/doctor.py`로 실행한다. 스크립트는 실행 위치가 아닌 자기 파일 위치를 기준으로 대상 프로젝트를 찾는다.
- Python 표준 라이브러리만 사용한다. Git 저장소, Claude Code 실행 환경, 별도 패키지 설치를 전제로 하지 않는다.
- 읽기 전용으로 동작한다. 파일 수정, 패키지 설치, 품질 프로필 및 테스트 실행, 유료·외부 호출을 하지 않는다.
- 모든 검사를 마친 뒤 `[PASS]`, `[WARN]`, `[FAIL]`과 수정 안내를 출력한다. FAIL이 하나라도 있으면 종료 코드 1, WARN만 있거나 전부 통과하면 0이다.

## 점검 범위

1. `CLAUDE.md`, `.claude/harness.json`, `.claude/settings.json`, `.claude/wiki/overview/README.md`, `.claude/wiki/knowledge/README.md`의 존재 여부를 확인한다. `AGENTS.md`는 Codex 사용 시 필요한 선택 항목으로 안내한다.
2. 두 JSON 파일의 문법과 핵심 구조를 확인한다. V2 설정의 `schema_version`, `history`, `quality.profiles.fast/full`, stage의 필수 필드와 명령 인자 형식을 검사한다. `harness.schema.json`의 계약과 모순되지 않게 한다.
3. `settings.json`의 훅 명령이 가리키는 프로젝트 내 스크립트가 있는지 검사하고, 품질 프로필의 트리거에 대응하는 훅 연결이 빠졌는지 확인한다. 기존 설정을 병합한 프로젝트도 고려한다.
4. 품질 stage의 `cwd`, 실행 파일 또는 `{python}` 경로와 치환값을 검사한다. 설정의 Python 경로가 없어서 다른 인터프리터로 대체되는 경우에는 사용자가 알 수 있게 경고한다.
5. 예시 프로젝트에서 아직 만들지 않은 `src/`, `tests/`, `.venv`, `pyproject.toml` 등은 설치 오류로 단정하지 않고 필요할 때 경고로 안내한다. Git 또는 Codex 전용 파일이 없는 것만으로 실패시키지 않는다.

## 구현 및 검증

- 스크립트와 핵심 검사 로직의 테스트를 추가한다. 임시 프로젝트를 이용해 정상 설정, 누락된 파일, 손상된 JSON, 끊어진 훅 경로, 잘못된 stage, Python 경로 대체, 경고만 있는 경우와 종료 코드를 확인한다.
- Windows와 Linux 경로를 고려한다. 검사 과정에서 설정된 stage 명령이나 외부 서비스를 실행하지 않았는지도 확인한다.
- `README.md`의 빠른 시작에 실행 시점, 명령, 오류·경고의 뜻을 간단히 설명한다.
- 저장소의 `AGENTS.md`와 `.claude/harness.json`에 따른 Fast·Full 품질 검사를 실행하고 결과를 보고한다. 기존 미추적 `.agents/`, `.codex/`는 건드리지 않는다.

## 완료 기준

새 프로젝트에서 한 번의 명령으로 설치 상태와 구체적인 수정 위치를 알 수 있으며, 설정이 깨져 훅이 조용히 비활성화되는 경우를 오류로 드러낸다.
