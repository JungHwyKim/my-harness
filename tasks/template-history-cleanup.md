# 범용 템플릿 배포와 초기 History 정리

- 작업 ID: `template-history-cleanup`
- 상태: 구현 대기
- 명세: `tasks/template-history-cleanup.md`
- 리뷰: `tasks/template-history-cleanup.review.md`
- 선행 작업: `tasks/quality-env-setup.md`에 연결된 기존 환경 구성 작업의 인수 종료 확인
- 이관 원본: `tasks/handoff.md:80`의 GitHub 배포·초기 상태와 관련 정리 항목
- 관계: 환경 구성과 별개의 후속 작업이다. 기존 환경 구축을 다시 수행하지 않는다.

## 목적

다른 프로젝트에 하네스를 적용할 때 설치 안내와 의존성 목록은 함께 배포하고,
로컬 가상환경과 하네스 개발 중 생성된 기록은 새 프로젝트의 초기 상태에서 제외한다.
이를 환경 구축 명세와 분리해 진행 중인 작업의 기준이 달라지지 않게 한다.

## 실행 계약

- 기존 환경 작업이 README 등 같은 파일을 수정하는 동안에는 구현을 시작하지 않는다.
  기존 작업의 보고와 인수가 끝난 뒤 이 명세를 기준으로 후속 작업을 진행한다.
- 이관 전 진행 중인 세션은 기존 경로로 작업을 마친다. 이후 템플릿 준비 요청과 보고는
  이 명세와 `tasks/template-history-cleanup.review.md`를 사용한다.
- 원본 `handoff.md`는 기존 세션을 위한 보존 문서로 둔다. 새 파일을 만든다고 기존
  세션이 자동 전환되거나 같은 작업을 두 번 실행하는 것은 아니다.
- 이 작업은 배포할 변경의 준비와 검증이다. GitHub에 실제 커밋·푸시하는 작업은 포함하지 않는다.

## 범위와 제외

- 포함: GitHub에 포함할 파일 구분, 새 프로젝트·기존 프로젝트의 적용 안내,
  초기 History의 공통 구조 유지, 보존을 확인한 기존 하네스 기록의 정리.
- 제외: 환경 재설치, requirements 버전 변경, 기존 프로젝트 기록 일괄 삭제,
  실행 시 자동 초기화, 훅·유료 테스트 승인·CI·Quality Profile 변경, 린트·테스트 실패 수정.
- 현재 명세·리뷰와 아직 진행 중인 다른 작업은 수정·개명·삭제하지 않는다.
- 명세 식별자 절차 변경은 `tasks/task-spec-identifiers.md`가 소유한다.

## 기존 코드 근거

- `tasks/handoff.md:80`에 설치 방법·의존성 배포와 초기 History 정리 요구가 섞여 있다.
  이 문서는 그 후속 범위만 분리하며 원본을 변경하지 않는다.
- `.claude/harness.json:3`, `:8`, `:9`, `:10`은 Wiki와 Plan·Task·Verify 기록 경로를
  정의한다. 빈 초기 폴더를 유지해 이 경로 계약은 보존한다.
- `.gitignore:5`는 `.venv/`를 제외한다. 환경 자체를 배포하는 대신 재생성 방법을 안내한다.
- `.claude/wiki/history/plan/2026-11-18-handoff-workflow.md`가 작업 트리에 있으며,
  분리 시점에는 미추적 상태다. 삭제 전에 다시 상태와 보존 여부를 확인한다.

1. `README.md`에 위 배포 구분과 초기 상태를 설명한다. pytest·ruff를 모든 대상
   프로젝트의 제품 의존성이나 필수 품질 도구라고 설명하지 않는다. 다른 언어 프로젝트는
   해당 도구에 맞게 Quality Profile을 구성하도록 안내한다.
2. 새 템플릿으로 시작하는 경우와 기존 프로젝트에 적용하는 경우를 구분한다.
   기존 프로젝트의 `requirements.txt`는 덮어쓰지 않는다. 하네스의 의존성 파일을
   `requirements-harness.txt`라는 별도 이름으로 가져와 필요한 검증 도구를 설치하는
   예시를 제공한다. 기존 가상환경·지침·프로젝트 설정도 덮어쓰지 않는다.
3. 현재 하네스 기록에서 지속되는 규칙은 공통 절차에 반영되어 있는지 확인한다.
   미래에도 필요한 결정 이유가 남으면 보존할 위치와 내용을 먼저 확보한다. 미추적
   파일이나 스테이징 상태만으로 Git에 보존됐다고 판단하지 않는다.
4. 보존 조건을 충족하면 현재 `2026-11-18-handoff-workflow.md`를 초기 History에서
   정리하고 공통 README와 세 `.gitkeep`를 유지한다. 필요한 정보를 보존할 수 없으면
   파일을 남겨 정리 미완료로 보고한다. 이 조건을 채우려고 임의로 커밋하지 않는다.
5. 배포 전에 완료된 임시 작업도 기존 완료·보존 조건으로 검토한다. 현재 진행 중인
   작업을 정리 대상으로 취급하지 않는다. 이후 새 프로젝트가 만드는 중요한 기록은
   기존 Plan·Task·Verify 절차대로 보존한다.
6. 배포할 브랜치의 추적 파일과 준비된 변경 목록을 확인한다. `.gitignore`는 이미 추적된
   기록을 제거하지 않는다. 진행 중인 명세나 미보존 기록이 남으면 그 상태를 보고하고,
   초기 상태 정리가 끝났다고 표시하지 않는다.

## 구현 및 검증

- README의 새 프로젝트·기존 프로젝트 설치 순서를 읽고 필요한 파일이 배포 대상에
  포함되는지 확인한다. 대상 프로젝트의 requirements·기록을 덮어쓰거나 삭제하는 안내가
  없어야 한다.
- `git check-ignore .venv/Scripts/python.exe`로 환경 제외를 확인한다. requirements와
  작업 템플릿은 무시되지 않아야 한다. History 전체에 대한 제외 규칙을 추가하지 않는다.
- History 파일 목록, 보존한 내용과 위치, 실제 정리한 파일, 배포 전 남은 작업을 리뷰에
  기록한다. 아직 진행 중인 작업이 있으면 최종 배포 준비 상태와 구분한다.
- 기존 Full 검사의 실패는 `tasks/handoff.review.md:186`에 보고되어 있다. 이 문서
  작업으로 해결됐다고 표시하지 않는다. 실행 코드·품질 설정을 바꾸지 않으므로 전용
  테스트를 새로 만들거나 전체 검사를 불필요하게 반복하지 않는다.
