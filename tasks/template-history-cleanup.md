## 목적

다른 프로젝트에 하네스를 적용할 때 설치 안내와 의존성 목록은 함께 배포하고,
로컬 가상환경과 하네스 개발 중 생성된 기록은 새 프로젝트의 초기 상태에서 제외한다.
이를 환경 구축 명세와 분리해 진행 중인 작업의 기준이 달라지지 않게 한다.

현재는 가상환경·requirements·기본 설치 안내와 `.agents/`·`.codex/` 제외 정책이 반영됐다.
설치·배포 안내와 THC-01·THC-02의 수정은 재리뷰에서 확인했다. 남은 작업은 아래 재리뷰에
명시한 상세 배포 절차의 영구 보존과 임시 작업 파일 정리이며, 실제 배포는 별도 단계다.
사용자가 선택한 배포 모델에 따라 `main`에는 History를 보존하고, 배포용 ref에서만 초기
History를 비운다. 이 작업의 준비·검증과 실제 배포 상태의 검증을 구분한다.

  있다면 해당 작업이 끝난 뒤 이 명세를 기준으로 후속 작업을 진행한다.
- 이관 전 진행 중인 세션은 기존 경로로 작업을 마친다. 이후 템플릿 준비 요청과 보고는

- 원본 `handoff.md`는 기존 세션을 위한 보존 문서로 둔다. 새 파일을 만든다고 기존
  세션이 자동 전환되거나 같은 작업을 두 번 실행하는 것은 아니다.
- 이 작업은 배포할 변경의 준비와 검증이다. GitHub에 실제 커밋·푸시하는 작업은 포함하지 않는다.
- 보고된 문서 커밋 `6286ec0`은 이미 수행된 결과로 검토한다. 이번 수정 요청은 추가 커밋,

  비우는 배포용 ref이며, History 삭제 커밋을 `main`으로 병합하지 않는다.

## Codex 초회 결과 리뷰 — 2026-11-20

검토 대상은 `main` / `6286ec0`의 구현과 현재 리뷰 보고다. 배포 ref 미생성 자체는 이번

횟수는 각각 0회다. 최신 판정과 남은 일은 문서 끝의 재리뷰를 따른다.

### THC-01 · P1 — 배포 커밋에 다른 작업의 변경이 포함될 수 있음

- 상태: 해결. 재리뷰의 worktree 격리 및 커밋 범위 확인 근거를 따른다.
- 위치: `tasks/template-history-cleanup.review.md:55-58`의 배포 명령 예시.
- 근거·재현 조건: 예시는 `git switch -c` 다음에 `git commit -a`를 실행한다. 현재
  `git diff --name-only`에는 `tasks/quality-env-setup.md`와 이 명세가 있다. 같은
  체크아웃에서 예시를 실행하면 두 파일의 변경이 새 브랜치에 따라가며 History 삭제와
  함께 커밋된다. 명령 예시의 결함이며 실제 배포 커밋을 만들어 재현하지는 않았다.
- 기대 동작·수정 방향: 깨끗한 별도 체크아웃을 사용하거나, 대상 경로와 기존 스테이징
  내용을 검사하고 History 삭제만 커밋하는 절차로 고친다. `git add`의 대상만 좁히고
  기존 스테이징 변경을 확인하지 않는 것으로는 충분하지 않다. 다른 작업의 변경을
  삭제·복원해 작업 트리를 강제로 깨끗하게 만들지 않는다.
- 검증 기준: 관련 없는 추적 파일의 변경이 있어도 배포용 커밋에 포함되지 않도록 절차가
  보장해야 한다. 격리된 검증 저장소에서 해당 조건을 확인하고, 커밋의 변경 파일 목록이
  의도한 History 기록 삭제로만 구성됨을 보고한다. 실제 배포 ref 생성은 요구하지 않는다.

### THC-02 · P2 — 얕은 복제에서 보존 커밋 조회 안내가 작동하지 않음

- 상태: 해결. 재리뷰의 로컬 커밋 전제 및 이력 조회 경로 확인 근거를 따른다.
- 위치: `README.md:28`의 `--depth 1`과 `.gitignore:11-12`의 보존 커밋 조회 안내.
- 근거·재현 조건: 배포 ref를 깊이 1로 복제하면 이전 커밋 `bfeb428`은 포함되지 않는다.
  따라서 해당 사본에서 안내된 `git show bfeb428:<기록 경로>`만으로는 기록을 읽을 수 없다.
  원본 저장소에는 보존 객체가 있음을 확인했다. Codex의 로컬 얕은 복제 시도는 Git의
  하위 프로세스 실행 환경 오류로 실패했으므로 실제 복제 재현에 성공했다고 주장하지 않는다.
- 기대 동작·수정 방향: 얕은 복제 사용자가 읽을 수 있는 원본 저장소의 보존 커밋·파일
  링크를 제공하거나, 필요한 이력을 가져오는 명시적인 절차를 안내한다. 로컬 `git show`만
  제공한다면 필요한 커밋이 로컬에 있어야 한다는 전제도 함께 명시한다.
- 검증 기준: 안내된 복제 방식과 기록 조회 방식이 일치해야 한다. 격리된 얕은 복제에서
  선택한 조회 경로를 검증하거나, 환경 제약으로 실행하지 못했다면 제약과 남은 검증을
  보고한다. 전체 테스트 통과만으로 이 문서 동작이 검증됐다고 표시하지 않는다.

### 보존·정리할 위치와 조건

새 문서를 늘리지 않고 이미 있는 `.claude/wiki/knowledge/template-deploy.md`를 배포하는

요구가 아니다. Claude는 인수인계 절차의 보존·정리 단계에서 다음을 반영한다.

1. 리뷰의 「The deploy-ref procedure」에 있는 상세 명령을 해당 Knowledge 문서로 옮긴다.
   현재 32–33행의 임시 리뷰 파일 안내를 영구 문서 안의 실제 절차로 대체한다. 명령 실행
   위치, 깨끗한 별도 worktree 사용, 기록 보존 확인, History 경로만 스테이징, 삭제 목록

2. `.gitignore`의 「배포 대상 전반은 `tasks/template-history-cleanup.md`가 소유한다」는
   참조를 README의 배포 파일 표와 위 영구 배포 계약으로 바꾼다. 임시 파일을 지운 뒤에도
   영구 문서가 현재 계약과 절차를 읽을 수 있는 경로를 제공해야 한다.
3. 보고서의 「수정 미커밋·미푸시」, 「`438dc3c`는 원격 참조에 없음」, 「절차가 임시
   파일에만 있음」은 수정 보고 당시의 상태다. 최종 정리 보고에서는 현재 상태와 구분한다.
   이번 확인에서 관련 변경은 커밋되어 있고, 두 보존 커밋은 로컬 `origin/main` 참조의
   이력에 포함되며, 영구 계약 문서도 있다. 원격 서버를 새로 조회한 결과로 표현하지 않는다.

- Codex는 현재 문서와 커밋, History 추적 목록, 기록 경로의 변경 없음, 로컬 디렉터리 제외와
