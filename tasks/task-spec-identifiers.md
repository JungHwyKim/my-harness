# 작업별 명세 식별자와 진행 중 변경 규칙

- 작업 ID: `task-spec-identifiers`
- 상태: 구현 가능 · 공통 절차와 템플릿에는 아직 미반영
- 최신화: 2026-11-19 · `main` / `bfeb428` 기준
- 명세: `tasks/task-spec-identifiers.md`
- 리뷰: `tasks/task-spec-identifiers.review.md`
- 선행 작업: 환경 구축은 완료 보고됨. 동일 파일을 편집 중인 세션이 없다면 진행 가능
- 관계: 이후 작업의 명세 작성 방식을 변경한다. 선행 명세를 대체하거나 범위를 추가하지 않는다.

## 목적

하나의 `handoff.md`에 서로 다른 후속 작업을 계속 추가하면 Claude가 구현을 시작한 뒤
기준이 달라진다. 앞으로는 작업의 핵심 내용을 식별자로 삼아 작업별 명세를 만들고,
진행 중인 명세에 새 요청을 섞지 않는다.

사용자의 요청부터 Codex의 새 명세 작성에 적용하고 있다. 다만 공통 절차와 템플릿의 실제
반영은 아직 남아 있다. 환경 구축을 다시 기다리지 않고 Claude가 이 문서의 범위로 구현한다.

## 현재 상태와 남은 작업

| 항목 | 2026-11-19 상태 | 이 작업에서 할 일 |
|---|---|---|
| 작업별 명세 분리 | 환경 구성·템플릿 정리·이번 작업이 각 ID의 파일로 존재함 | 실제 문서 분리 방식을 공통 절차로 고정 |
| 인수인계 절차 | 명세를 제자리에서 고친다는 안내가 남음 | 초안 수정·리뷰 반영과 진행 중 변경의 경계를 명시 |
| 명세 템플릿 | ID·상태·선행 작업·관계 필드가 없음 | 필드와 작성 예시 추가 |
| 템플릿 소유자 | 「이 절차와 함께 유지한다」로만 표기됨 | 명세 작성 담당인 Codex로 명시 |
| 환경 구축 선행 조건 | 환경 완료·최신 Full 통과가 리뷰에 보고됨 | 이미 끝난 작업을 미완료 의존성으로 남기지 않음 |

이 문서는 구현 명세다. 이 파일을 갱신한 것만으로 공통 절차와 템플릿의 반영이 완료된 것은
아니다. 결과는 별도 `tasks/task-spec-identifiers.review.md`에서 확인한다.

## 실행 계약

- 명세 경로는 `tasks/<작업-ID>.md`, 리뷰·구현 보고 경로는
  `tasks/<작업-ID>.review.md`다. 두 파일은 같은 작업 ID를 사용한다.
- 작업 ID는 작업의 목적과 대상을 드러내는 영문 소문자와 하이픈으로 쓴다.
  명세의 작업 ID, 파일 이름, 리뷰 이름은 서로 같아야 한다.
- `handoff.md`, `plan.md`, `task.md` 같은 범용 이름을 새로운 작업의 공용 명세로
  재사용하지 않는다. 날짜나 `v2`만으로 작업을 구분하지 않는다.
- 문서 절차 변경이며 실행 프로그램과 종료 코드를 추가하지 않는다.

## 범위와 제외

- 포함: 명세 파일명, 작업별 메타데이터, 진행 중 명세의 변경 경계, 후속 작업의 관계를
  공통 인수인계 절차와 명세 템플릿에 반영한다.
- 제외: 이미 끝난 가상환경·requirements 작업, 그 결과와 리뷰, 기존 파일의 일괄 개명,
  작업 파일의 이동·삭제, 훅·CI·세션 자동 연결.
- `tasks/handoff.md`와 `tasks/handoff.review.md`는 이 작업에서 수정하거나
  이름을 바꾸지 않는다. 다른 작업의 보존·정리는 `tasks/template-history-cleanup.md`가
  소유하며, 이 명세는 절차와 템플릿의 작성 규칙만 바꾼다.

## 기존 코드 근거

- `.claude/skills/handoff/SKILL.md:22`와 `:23`은 명세와 리뷰의 소유자를 분리한다.
  작업별 ID를 도입해도 이 소유 관계는 유지한다.
- `.claude/skills/handoff/SKILL.md:29`와 `:47`은 Codex가 원래 명세를 제자리에서
  고치도록 안내하지만, Claude가 이미 작업 중인 경우의 변경 경계는 적지 않았다.

  후속 관계를 적는 필드를 추가해 범용 파일의 계속된 재사용을 막는다.
- `.claude/skills/handoff/SKILL.md:24`는 템플릿 담당을 한 명으로 지정하지 않는다.
  기존 리뷰 F2와 연결되는 부분이므로 이 작업에서 Codex의 소유로 명확히 한다.
- `tasks/handoff.review.md:367`의 잔여 항목은 이 명세의 환경 선행 조건이 끝났다고
  보고한다. `:380`의 마지막 절은 F6 종료와 최신 Full 통과를 보고한다.

## 구현 범위

1. `.claude/skills/handoff/SKILL.md`에 다음 작성 규칙을 반영한다.
   - 새로운 작업은 고유한 작업 ID와 새 명세 파일을 갖는다. 기존 파일을 덮어쓰지 않는다.
   - 작성 전에 같은 경로가 있는지 확인한다. 같은 이름의 다른 작업이 있으면 대상·변경
     목적을 더 구체적으로 붙여 구분한다. 삭제된 기존 작업의 ID도 다른 작업에 재사용하지
     않는다. 필요하면 `git log --all -- tasks/<작업-ID>.md`로 기존 이력을 확인한다.
   - 초안은 Codex가 같은 파일에서 다듬을 수 있다. Claude가 검토·구현 중인 명세는
     본문과 경로를 유지한다.
   - 새 작업, 범위 추가, 요구 변경은 핵심 내용을 나타내는 새 ID의 명세로 만든다.
     기존 명세를 복사한 경쟁 문서가 아니라 변경 내용과 선행 관계가 명확한 후속 작업으로
     쓴다. 후속 작업을 만들었다는 이유로 진행 중 작업의 기준이 바뀌지 않는다.
   - 같은 작업의 리뷰를 반영해 원래 명세를 고치는 경우에는 Claude의 해당 단계가
     끝나 파일을 읽고 작업 중인 에이전트가 없는지 확인한다. 원래 작업의 수정 요청을
     처리할 때만 사용하며, 별도 작업을 기존 명세에 추가하는 수단으로 쓰지 않는다.
   - 후속 명세에는 선행 작업과 관계를 적는다. 같은 구현 파일을 바꾸는 후속 작업은
     선행 작업이 끝난 뒤 수행한다. 파일명 분리만으로 구현 충돌이 사라진다고 보지 않는다.
   - 명세의 상태 표기는 Claude에게 명세 수정 권한을 주지 않는다. Claude의 검토·실행
     상태와 결과는 같은 작업 ID의 리뷰 파일에 적는다.
2. `tasks/_template.md`의 머리에 작업 ID, 상태, 명세·리뷰 경로, 선행 작업, 관계를
   적는 필드를 추가한다. 선행 작업이 없으면 「없음」, 이미 끝났으면 완료 근거를 적는다.
   - 관계는 신규 작업·후속 작업 등 기존 명세와의 관계를 밝히는 항목이다. 후속 작업이면
     선행 명세 경로와 바뀌는 범위를 적고, 진행 중인 원본을 자동 대체하지 않는다고 명시한다.
   - `_template.md`는 작업별 임시 명세가 아닌 영구 템플릿이며 소유자는 Codex다.
     공통 절차의 소유 표와 템플릿 안내를 일치시킨다.
3. 절차의 원본은 기존 인수인계 문서 한 곳으로 유지한다. `CLAUDE.md`와 `AGENTS.md`에
   같은 상세 규칙을 복제하지 않는다. 기존 기록·보존·정리 정책도 유지한다.
4. `tasks/task-spec-identifiers.review.md`에 변경 파일, 확인한 규칙, 미해결 사항을
   영어로 보고한다. 기존 `tasks/handoff.review.md`에 섞지 않는다.

## 구현 및 검증

- 변경한 절차와 템플릿을 읽고 신규 작업에 ID가 부여되는지, 리뷰가 같은 ID를 쓰는지,
  진행 중 명세와 후속 작업의 관계가 구분되는지 확인한다.
- 「제자리 수정」 안내를 포함해 전체 절차에 진행 중 명세의 변경 금지와 상충하는 문장이
  남지 않았는지 확인한다. 예시의 경로 대응과 참조 대상도 확인한다.
- 초안 수정, 진행 중 변경 요청, 완료된 리뷰 반영, 기존 ID 충돌, 끝난 선행 작업의 다섯
  경우를 문서 예시에 대입해 기대 경로와 다음 행동이 구분되는지 확인한다. 실제 사용하지
  않을 빈 작업 명세·리뷰를 검증용으로 생성하지 않는다.
- 문서만 변경하는 작업이므로 전용 테스트는 추가하지 않는다. 코드 품질 검사를
  실행하지 않았다면 문서 변경이라는 이유를 보고한다.

## 완료 기준

- 새 작업을 범용 `handoff.md`에 추가하도록 안내하는 규칙이 없다.
- 명세 템플릿에 작업 ID와 경로, 선행 관계를 기록할 자리가 있다.
- 진행 중 명세는 고정되고, 새 요청은 별도 ID의 후속 명세로 구분된다.
- 공통 절차와 템플릿의 소유·상태 설명이 일치하고, 템플릿 소유자가 Codex로 명시된다.
- 이미 끝난 환경 구성과 삭제된 훅 명세를 미완료 선행 작업으로 표시하지 않는다.
- 기존 진행 중 파일을 개명·이동·수정·삭제하지 않았고, 결과는 이 작업의 리뷰에 기록된다.
