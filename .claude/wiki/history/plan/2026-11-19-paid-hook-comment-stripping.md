# 비용 훅에서 셸 주석 제거 전처리를 폐기한다

- 날짜: 2026-11-19
- 상태: 승인
- 영향 범위: `.claude/harness/hooks/paid_test_check.py`의 판정 입력,
  `knowledge/paid-test-approval.md`의 승인 범위 계약, 유료 pytest 호출을 쓰는 모든 세션

## 결정할 문제

비용 훅은 「이 명령이 유료 마커를 고르거나 기본 제외를 덮는가」를 명령 **문자열**에서
판정한다. 그 판정 앞에 전처리 한 단계가 있었다 — `_strip_comment()`가 셸 주석을 지운
뒤에 마커·설정 옵션을 찾았다.

전처리의 의도는 「주석 안의 글자로 판정을 뒤집지 못하게」였다. 그런데 주석 경계를
명령 문자열만으로 증명하려는 규칙이 매번 새 우회의 통로가 됐다. 규칙을 세 번 덧댔다.

1. `#`은 토큰 머리에서만 주석이다 — 무조건 자르면 `pytest ./foo# -m paid -q`에서 뒤의
   `-m paid`가 사라져 통과했다.
2. 따옴표 **안**의 `#`은 주석이 아니다 — `git commit -m "fix #123"`을 깨뜨리지 않으려고.
3. 이스케이프된 공백은 토큰 경계가 아니다 — CDEX-08 대응.

그래도 CDEX-08이 남았다. ``pytest -q -o junit_suite_name=x` # -m paid``는 백틱(Bash는
역슬래시)이 **공백**을 이스케이프해 `#`을 `-o` 값 안에 넣는다. 그러면 `#`은 주석이 아니고
뒤의 `-m paid`는 진짜 옵션인데, 주석 제거가 그 지점에서 잘라 `-m paid`를 지워 버렸다.
두 셸 모두에서 유료 본문이 실제로 실행되는 것을 표식 파일로 확인했다.

세 번 덧댄 규칙이 세 번 다 **같은 모양으로** 틀렸다는 것이 문제의 핵이다.

## 검토한 선택지

1. 주석 제거를 유지하고 CDEX-08만 막는다(Round 8의 좁은 수정). 이스케이프 판정을
   `_escapes_next()` 한 곳으로 모으고 따옴표 밖에서도 이스케이프를 인정한다.
2. 전처리 자체를 폐기한다. `_paid_reason()`에 세그먼트 **원문**을 넘기고
   `_strip_comment()`·`_walk()`·`_escapes_next()`를 제거한다.
3. 셸 문법을 제대로 해석한다 — PowerShell·Bash의 파서를 각각 흉내내거나 실제 셸에
   물어본다.

## 결정

선택지 2를 고른다.

- 판정은 세그먼트 원문 그대로 한다. 셸 주석을 지우지 않고, 이스케이프도 추적하지 않는다.
- `_strip_comment()`·`_walk()`·`_escapes_next()`를 제거한다. 이 세 함수는 서로만
  부르고 있었다(훅 −62줄).
- **진짜 주석에 위험 옵션이 적힌 호출도 승인 대상이 된다.** `pytest -q # -m paid`,
  `pytest -q -o junit_suite_name=x # -m paid`, 그리고 유료 마커를 고르지 않더라도 기본
  제외를 덮을 수 있는 `pytest -q # -m unit`·`# -c other.ini`·`# -o addopts=`가 그것이다.
  이 오탐을 계약으로 못 박는다.
- 남는 문자열 해석은 토큰 분리(`shlex`, `posix=False`)와 첫 토큰의 실행기 식별뿐이다.
  토큰 분리가 실패하면 묻는 쪽으로 떨어진다. **실행기 식별은 그렇지 않다** — pytest,
  python, `uv`·`tox` 같은 러너, 변수만 판정 대상이고 래퍼 스크립트나 `make`처럼 모르는
  첫 토큰은 아예 판정하지 않아 통과한다(`./run_tests.sh -m paid` 실측). 이 결정이 바꾸지
  않은 기존 한계이고, `knowledge/paid-test-approval.md`의 「감지하지 못하는 것」에 있다.

## 이유

- **전처리 단계가 없으면 그 단계를 노리는 우회도 없다.** 이 훅에서 나온 우회 여덟 건은
  전부 「이 글자가 진짜 옵션인가/진짜 주석인가」를 문자열로 가리려는 자리를 과녁으로
  삼았다. `--collect-only` 예외를 같은 이유로 이미 없앴는데, 주석 제거는 같은 모양인 채로
  남아 있었다. CDEX-08은 남은 그 한 군데로 들어왔다.
- **선택지 1은 네 번째 덧댐이다.** 실제로 CDEX-08을 막았지만, 막은 방식이 「이스케이프
  규칙을 한 겹 더 정확하게」였다. 앞의 세 번도 같은 방식이었고 같은 모양으로 뚫렸다.
  다음 셸 문법을 열거하는 리뷰 회차를 늘릴 뿐이라고 봤다.
- **오탐의 방향이 안전하다.** 주석 경계를 증명하려던 규칙은 **반대 방향으로도** 틀렸다 —
  CDEX-08에서 진짜 `-m paid`를 주석으로 잘라 승인 없이 유료 본문을 실행했다. 전처리를
  걷어낸 뒤의 오탐은 과금되지 않는 명령에 승인창이 한 번 더 뜨는 것뿐이다. 유료 호출을
  놓치는 것과 값이 다르다.
- **오탐의 경계가 분명하다.** 판정은 원문 전체를 보므로, 안전한 마커 식이 앞에 있어도
  주석에 `-m unit`이나 `-c other.ini`가 있으면 묻는다(실측). 통과하는 것은 기본 제외를
  덮을 수 있는 글자가 원문 어디에도 없을 때다 — `pytest -q # 설명`,
  `pytest -m 'not paid and not paid2' # 설명`. 일상 호출과 설명만 적은 주석은 영향이
  없고, 오탐은 위험 옵션을 적어 둔 주석에만 생긴다.
- **선택지 3은 비용 경계에 둘 만한 복잡도가 아니다.** 두 셸의 파서를 흉내내는 것은 이
  훅이 이미 세 번 실패한 일의 더 큰 판본이고, 실제 셸에 물어보는 것은 판정하려는 명령을
  실행하는 것과 구분이 어렵다.

## 기각한 대안

- **Round 8의 좁은 수정 유지(선택지 1)** — CDEX-08은 막지만 위험한 전처리 단계가 남는다.
  네 번째 덧댐이 되고, 과녁이 그대로다.
- **셸 파서 구현 또는 실제 셸 질의(선택지 3)** — 비용 경계에 맞지 않는 복잡도다. 후자는
  판정 대상을 실행하는 쪽으로 번진다.
- **주석을 지우되 이스케이프가 보이면 보수적으로 묻기** — 「이스케이프가 보이는가」가 또
  하나의 문자열 판정이다. 같은 실패 모양을 한 겹 옮기는 것일 뿐이다.
- **오탐을 없애려고 `#` 뒤를 무시하되 이스케이프된 `#`만 살리기** — 정확히 CDEX-08에서
  틀린 규칙이다.

## 영향과 후속 조건

측정(무과금 임시 프로젝트, 마커 `paid`·`paid2`, 2026-11-19):

- 훅 판정 — 승인 대상 7건이 모두 `ask`, 통과 대상 7건이 모두 무응답(allow),
  `plan`·`bypassPermissions`·모드 누락은 모두 `deny`.
- 실제 셸 실행 — `pytest -q # -m paid`는 PowerShell과 Bash 모두에서 `unit`만 실행했다.
  셸이 주석으로 보고 `-m paid`를 pytest에 넘기지 않는다는 뜻이고, **받아들인 오탐이
  과금되지 않는다는 근거**다. CDEX-08 두 형태는 두 셸 모두에서 `paid`를 실행했다 —
  훅이 반드시 물어야 하는 이유다.
- 훅을 거치지 않는 경로 — Quality Profile의 pytest는 하위 프로세스라 `PreToolUse`를
  거치지 않는다. README 예시의 기본 `pytest -q`와 Fast/Full argv 둘 다 유료 표시 테스트를
  고르지 않았다(각각 1 passed, 2 deselected). 그 경로의 보호는 훅이 아니라 설정의 기본
  제외라는 것이 확인된 셈이다.
- Full Quality Profile — ruff check·format 통과, pytest 405건 통과. 회귀 테스트는
  받아들인 오탐 다섯 건을 승인 대상으로 옮겨 계약을 고정했다.

남은 조건:

- 이 결정의 검증 범위는 **문서화한 직접 pytest 호출과 이미 재현한 우회**뿐이다. 임의의 셸
  문법 전체를 지원한다고 주장하지 않는다. 새 우회가 나오면 전처리를 되살리는 쪽이 아니라
  이 범위를 다시 보는 쪽으로 판단한다.
- 명세의 다른 항목은 모두 끝났다. `.codex/hooks.json`에서 비용 훅 항목은 이미 빠져
  있었고, `.codex/` 자체를 추적하지 않기로 한 결정은 `ce4b701`과
  `history/plan/2026-11-19-codex-dir-tracking.md`에 있다. README의 적용 예시(마커 등록,
  pyproject의 `addopts` 제외, Fast/Full argv의 제외)는 `README.md`에 들어가 있고, 위
  측정이 그 예시가 실제로 유료 테스트를 고르지 않는 것까지 확인했다.
- 이 결정 이전의 회차별 경과(우회 여덟 건의 재현과 회차별 수정)는 `tasks/` 작업 파일
  둘에 있었다. 인수인계 절차에 따라 정리 단계에서 지웠으므로, 지금 읽을 수 있는 곳은
  커밋 `860fd7b`와 그 뒤의 정리 커밋이다. 남겨야 할 이유는 이 문서가 갖는다.

## Knowledge 반영

`knowledge/paid-test-approval.md`에는 **지금 지켜야 할 규칙만** 반영했다.

- 판정 표의 셸 주석 행을 「지우지 않는다. 원문에 위험 옵션이 보이면 주석이든 아니든 승인
  필요」로 바꿨다.
- 「명령을 읽는 규칙」에서 주석 경계·이스케이프 규칙 표를 지웠다. 그 코드가 없다.
- 「받아들인 오탐」 절을 새로 두고 다섯 명령과 셸의 실제 동작을 적었다. 경계는 「안전한
  식이 있으면 통과」가 아니라 「원문 어디에도 기본 제외를 덮을 글자가 없어야 통과」다.

기각한 대안과 세 번 덧댄 경과는 복제하지 않고 이 문서에만 둔다.
