# 유료 테스트 승인 계약

비용이 드는 pytest 실행을 Claude Code가 하기 전에 **호출마다** 사용자 승인을 받는다.
`paid_test_check.py`가 `PreToolUse`에서 판정하고, 보호는 아래 세 곳이 함께 서야 성립한다.

## 보호가 서는 세 자리

| 자리 | 하는 일 | 없으면 |
|---|---|---|
| `checks.expensive_tests.pytest_markers` | 무엇이 유료인지 프로젝트가 정한다 | 훅이 아무것도 감지하지 않는다 |
| 프로젝트 pytest 기본 `addopts` | 마커를 지정하지 않은 호출에서 유료를 제외한다 | `pytest -q`가 유료까지 수집한다 |
| Quality Profile의 `argv` | Fast·Full 자식 pytest에서 제외한다 | 게이트가 훅을 거치지 않고 유료를 돌린다 |

세 번째가 따로 필요한 이유는 `_quality.py`가 stage를 `subprocess`로 직접 띄우기 때문이다.
그 경로는 `PreToolUse`를 지나지 않으므로 훅이 볼 기회가 없다.

이 템플릿 저장소의 마커 목록은 `[]`다. 제품 테스트가 없으므로 그것이 맞고, 빈 목록이면
훅은 아무 판정도 하지 않는다.

## 판정 규칙

훅은 **명령줄이 기본 제외를 덮는지**만 본다. 명령줄 `-m`은 설정의 `addopts`보다 뒤에
적용되므로, `-m`이 있으면 우리가 아는 제외가 남아 있다고 볼 수 없다.

그래서 «유료를 고르나»가 아니라 **«유료를 다 빼나»**로 묻는다. `or`도 괄호도 없는 단순
AND 식에서 설정된 모든 마커가 `not <마커>`로 빠지는 것이 보일 때만 통과시킨다.
문자열 eval은 쓰지 않는다.

| 명령 | 판정 |
|---|---|
| `-m` 없음 (`pytest -q`) | 통과. 설정의 기본 제외를 전제한다 |
| `-m 'not paid and not paid2'` (설정 마커 전부) | 통과 |
| `-m unit`, 빈 `-m`, `-m 'not paid or unit'` | 승인 필요 |
| `-m 'not paid'` (마커가 둘인데 하나만) | 승인 필요 |
| 괄호·복합식 | 해석하지 않고 승인 필요 |
| `-m` 반복 | 하나라도 증명되지 않으면 승인 필요 |
| `-c`·`--config-file` | 승인 필요. 그 설정의 제외를 알 수 없다 |
| `-o`/`--override-ini addopts=` | 덮어쓴 값이 전부 빼지 않으면 승인 필요 |
| `--collect-only` | **예외 없음.** 유료 마커를 고르거나 기본 제외를 덮으면 승인 필요 |
| 셸 주석(`# ...`) | **지우지 않는다.** 원문에 위험 옵션이 보이면 주석이든 아니든 승인 필요 |
| pytest가 아닌 명령 | 관여하지 않는다 |

## `--collect-only` 예외를 없앤 이유

수집만 하면 과금이 없다는 것은 사실이다. 그런데 이 훅에서 나온 **우회 여덟 건이 전부 그
예외를 과녁으로 삼았다** — 주석 속의 글자, `./--collect-only` 라는 경로 이름, 인용 문자열
안의 글자, PowerShell 백틱과 Bash 역슬래시로 따옴표를 속이는 두 가지.

공통 원인은 하나다. 「이 `--collect-only` 가 **진짜 옵션인가**」를 문자열 검사만으로
가리려 한 것이다. 두 셸의 인용·이스케이프 규칙을 그렇게 완전히 판별할 수 없다.

그래서 비용 경계에서는 예외를 없앴다. 유료 마커를 고르는 명령은 `--collect-only` 가
어디에 붙어 있어도 승인을 묻는다. **잃는 것은 하나뿐이다** — 유료 테스트 목록을 수집만 해
보려는 호출에 승인창이 한 번 더 뜬다. 안전한 일반 호출은 예외가 없어도 그대로 통과한다.

## 명령을 읽는 규칙

**셸 문법을 해석하지 않는다.** 주석 제거와 이스케이프 추적은 폐기했다 — `#`의 주석 경계나
`\`·`` ` ``의 이스케이프를 문자열 검사로 증명하려던 규칙이 매번 새 우회의 통로였다.
판정은 세그먼트 원문 그대로 한다.

| 읽는 규칙 | 왜 |
|---|---|
| 판정은 **원문 그대로** 한다 | 전처리 단계가 없으면 그 단계를 노리는 우회도 없다 |
| 마커·설정 옵션은 원문에서 정규식으로 찾는다 | `#` 뒤에 있든 따옴표 안에 있든, 보이면 묻는다 |
| 첫 토큰이 pytest 실행기인 세그먼트만 본다 | `git commit -m "paid 마커 추가"`에 승인창이 뜨면 훅이 통째로 무시당한다 |
| 토큰 분리는 `shlex`(`posix=False`)로 한다 | `split()`만 쓰면 공백이 든 경로의 첫 토큰이 `"C:\Program`이 되어 실행기를 못 알아보고 유료 명령이 통째로 샌다 |
| 따옴표가 안 닫혀 분리에 실패하면, `pytest`라는 말이 있으면 pytest로 본다 | `split()`으로 떨어지면 바로 위 구멍이 되살아난다. 틀리는 방향을 «묻는» 쪽으로 둔다 |

## 받아들인 오탐

진짜 셸 주석에 위험 옵션이 적힌 호출에도 승인창이 뜬다.

| 명령 | 셸의 실제 동작 | 훅 판정 |
|---|---|---|
| `pytest -q # -m paid` | `-m paid`를 pytest에 넘기지 않는다 | 승인 필요 |
| `pytest -q -o junit_suite_name=x # -m paid` | 같다 | 승인 필요 |
| `pytest -q # -m unit` | 같다 | 승인 필요 |
| `pytest -q # -c other.ini` | 같다 | 승인 필요 |
| `pytest -q # -o addopts=` | 같다 | 승인 필요 |

**유료 마커를 고르는 글자만이 아니다.** 기본 제외를 덮을 수 있는 글자가 원문에 있으면
주석 안이어도 묻는다 — 증명되지 않는 `-m`, 다른 설정을 고르는 `-c`·`--config-file`,
`addopts`를 덮는 `-o`·`--override-ini`가 모두 그렇다.

과금되지 않는 명령에 한 번 더 묻는 쪽을 고른 것이다. 주석 경계를 증명하려던 규칙은
**반대 방향으로도** 틀렸다 — 이스케이프된 공백 때문에 진짜 `-m paid`가 주석으로 잘려
승인 없이 유료 본문이 실행된 사례가 있다.

경계는 하나다 — **원문 어디에도** 기본 제외를 덮을 수 있는 글자가 없어야 통과한다.
안전한 마커 식이 앞에 있다고 통과하는 것이 아니다.
`pytest -m 'not paid and not paid2' # -m unit`과 `... # -c other.ini`는 앞의 식이
안전해도 묻는다(실측). 통과하는 것은 그런 글자가 아무 데도 없을 때다 —
`pytest -q # 설명`, `pytest -m 'not paid and not paid2' # 설명`,
`pytest -q # --collect-only`.

## 권한 모드별 응답

승인 필요로 판정된 명령에만 적용한다.

| `permission_mode` | 응답 |
|---|---|
| `default`, `acceptEdits`, `auto` | `ask` |
| `plan`, `dontAsk`, `bypassPermissions` | `deny` |
| 누락·알 수 없는 값 | `deny` |

**기본이 `deny`인 것이 설계다.** 승인창이 뜨지 않는 환경에서 `ask`를 내면 그대로 실행될
수 있고, 그때 아무 신호도 남지 않아 보호가 있다고 착각하게 된다.

## 환경변수 우회는 없다

예전에는 `ALLOW_PAID_TESTS=1`이 탈출구였다. 값이 비어 있지 않은지만 봐서 `=0`도
통과했고, 한 번 켜면 세션의 모든 유료 테스트가 열렸다. 승인으로 바꾸면서 없앴다 —
설정의 `allow_env`와 스키마 정의도 함께 지웠다. 허용의 단위는 이제 세션이 아니라 도구
호출 하나다. 기존 프로젝트를 옮길 때는 그 두 설정과 환경변수 사용을 함께 지운다.

## 감지하지 못하는 것

- 마커가 붙지 않은 유료 테스트. 무엇이 유료인지는 프로젝트가 마커로 알려줘야 한다.
- pytest 밖에서 직접 호출하는 유료 API.
- 변수나 래퍼 스크립트에 숨긴 실행 명령. 정적 판정의 한계다.
- Codex에서는 이 훅을 쓰지 않는다. Codex의 `PreToolUse`는 `ask`를 지원하지 않고 오류를
  보고한 뒤 도구 호출을 계속하므로, 배선해 두면 보호가 없는데 있는 것처럼 보인다.
  그래서 `.codex/hooks.json`에서 이 훅만 뺐다. 단 `.codex/`는 저장소가 추적하지 않으므로
  (`.gitignore`) 그 파일은 머신마다 따로 있고 클론에는 없다.

## 실제로 확인한 것 (2026-11-19)

Windows의 Claude Code, `PowerShell` 도구 경로에서 사용자가 승인창을 직접 조작해 확인했다.
무과금 probe 프로젝트를 쓰고 실제 API는 호출하지 않았다.

| 확인 | 결과 |
|---|---|
| `default`에서 승인창이 뜨는지 | 뜬다. 하네스가 `Hook PreToolUse:PowerShell requires confirmation`으로 출처를 밝히고 사유가 그대로 나온다 |
| 거절 | 실행되지 않는다 |
| 승인 | 실행된다 |
| 승인 뒤 같은 명령 재요청 | **다시 묻는다.** 승인이 호출을 넘어 이어지지 않는다 |
| `permissions.allow`로 `Bash`·`PowerShell`을 통째 허용 | 그래도 호출마다 묻는다 |
| `bypassPermissions` | `deny`로 막힌다 |
| 비대화형(`claude -p`) | 유료 테스트가 실행되지 않는다 |

승인창에는 **「다시 묻지 않기」 선택지가 없다.** 훅의 `ask`는 억제할 수 있는 도구 권한이
아니라서, 클릭 한 번으로 상시 허용으로 바꿀 수 없다. 일반 Bash 확인창과 구별되는 표시이기도
하다.

훅을 거치지 않는 경로도 확인했다. Quality Profile의 pytest는 도구 호출이 아니라 하위
프로세스로 돌아 `PreToolUse`를 거치지 않는다. 무과금 임시 프로젝트에서 README 예시의
기본 `pytest -q`와 Fast/Full argv(`-m "not paid and not paid2"`)가 둘 다 유료 표시
테스트를 고르지 않았다(각각 1 passed, 2 deselected). **그 경로의 보호는 훅이 아니라
설정의 기본 제외다.**

## 아직 관찰하지 못한 것

- `acceptEdits`·`auto`의 실제 승인창. `_decision_for_mode()` 단위 테스트로만 덮여 있다.
- `plan`·`dontAsk`. `plan`은 이 훅과 무관한 이유로 명령 실행을 막으므로, 거기서 안 돌았다고
  해서 훅의 보호라고 말할 수 없다.

덮여 있다는 것과 본 것은 다르다. 위 둘은 **본 적 없음**으로 둔다.

## 비대화형 보호는 우리 것이 아니다

`claude -p`에서 유료 테스트가 안 돈 것은 모드가 `default`여서 훅이 `ask`를 냈고, **답할
사람이 없는 승인을 하네스가 진행하지 않았기** 때문이다. 우리 `deny` 분기가 막은 것이 아니다.

payload로는 `-p`와 대화형 `default`를 구분할 수 없으므로 훅 쪽에서 더 조일 방법이 없다.
보호는 실재하지만 이 훅의 통제 밖에 일부 있다. 하네스가 나중에 비대화형에서 `ask`를 자동
승인하도록 바뀌면 이 경로는 다시 열린다.

승인 없이 실행되는 경로가 관찰되면 그 경로는 `deny`로 되돌린다.
