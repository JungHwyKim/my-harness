# quiz

**이 스킬이 하는 일은 문제를 내는 것이 아니라 「말이 나오는가」를 재는 것이다.** 노트를
읽으면 다 아는 것 같고, 막상 물으면 안 나온다. 그 간격을 보이게 하는 것이 전부다.

**채점 기준을 지어내지 않아도 된다는 것이 이 도구의 전제다** — 사람이 쓴 모범답안이 질문
54개·꼬리질문 108개로 실재한다. 그 전제가 깨지는 자리(저장소에서 만든 질문)는 4단계에서
따로 다룬다.

## 0단계 — 노트 파일을 직접 읽지 않는다

`면접노트.html` 은 **96,382 토큰**이라 `Read` 가 25,000 에서 자르는데 **잘렸다는 신호가 안
온다**. 마크다운 여덟 개를 다 읽는 것도 85,266 토큰을 문맥에 붓는 것이다. 수집은 스크립트가
한다.

```bash
python "${CLAUDE_PROJECT_DIR}/.claude/harness/scripts/quiz/collect.py" --count 5
```

**stderr 의 경고를 반드시 읽고 사용자에게 옮긴다.** 경고는 파서가 노트의 새 형태를 못
알아봤다는 신호이고, 그때 문항 목록은 실제보다 **짧다**. 조용히 짧아지는 것이 이 도구의
유일한 실패 모드다.

**멈추면 그대로 멈춘다.** 노트를 고친 뒤 마크다운을 다시 안 뽑았으면 수집기가 사유를 찍고
죽는다. **우회해서 진행하지 않는다** — 낡은 답으로 채점하면 사용자가 **맞는 답을 하고도
틀렸다고 듣고**, 그 지적을 믿고 답을 고치면 준비가 거꾸로 간다. 시키는 대로 옮긴다.

```powershell
.\.venv\Scripts\python.exe C:\Users\junghwy\Documents\면접준비\_html2md.py
```

### 고르는 인자

| 인자 | 하는 일 |
|---|---|
| `--count N` | 앞에서 N개 |
| `--seed N` | 이 씨앗으로 섞는다 (같은 씨앗이면 같은 순서) |
| `--star` | ★ 문항만 (제일 자주 나오는 질문들) |
| `--file 03-검색` | 이 단원만 |
| `--ids a,b` | 이 문항만 |
| `--weak` | 지난 회차에 지적이 있었던 문항만 |
| `--answers` | **모범답안과 꼬리질문을 싣는다** |

## 1단계 — 회차를 열 때 모드를 한 번 묻는다

> 구술로 하시겠습니까, 쓰기로 하시겠습니까?
> **구술** — 소리 내어 말하고, 말한 것을 그대로 옮겨 적습니다. 말투까지 봅니다
> **쓰기** — 요점만 적으셔도 됩니다. 내용만 봅니다

**문항마다 다시 묻지 않는다.** 그 회차 내내 유지한다. 사용자가 도중에 바꾸겠다고 하면 바꾼다.

**답의 길이로 알아서 판정하지 않는다.** 정성껏 쓴 쓰기 답이 구술로 잡히면 말투를 재게 되는데,
그것이 이 모드가 없애려는 바로 그 지적이다.

몇 문제를 낼지도 함께 정한다. 안 말하면 **5문제**로 하고 그렇게 말한다.

## 2단계 — 한 문제의 진행

1. **문제 하나를 낸다.** `--answers` **없이** 뽑은 것이라 이 시점에 모범답안을 안 보고 있다.
   그것이 규약이다 — 답을 보고 있으면 힌트가 새고, 사용자는 그것을 눈치채지 못한다
2. **사용자가 답할 때까지 다음으로 안 간다.** 힌트도 먼저 안 준다. 사용자가 «모르겠다» 고
   하면 그때 답을 펼치고 넘어간다
3. 답을 받으면 **그 문항의 답만** 가져와 대조한다

   ```bash
   python "${CLAUDE_PROJECT_DIR}/.claude/harness/scripts/quiz/collect.py" --ids <id> --answers
   ```

4. 3단계대로 짚는다
5. **꼬리질문을 이어 던진다.** 노트에 108개가 답안까지 딸려 있고, 실제 면접의 모양이 그것이다.
   한 문항에 하나면 충분하고, 사용자가 막히면 더 안 던진다
6. 4단계로 기록을 남기고 다음 문제로

**문항을 낼 때 단원 이름과 ★ 여부를 함께 보인다** — 어느 갈래에서 막히는지가 사용자에게
보여야 한다.

## 3단계 — 채점 기준은 점수가 아니다

내놓는 것은 네 목록이고, **모드가 무엇을 켜는지 가른다.**

| 칸 | 뜻 | 구술 | 쓰기 |
|---|---|---|---|
| `missed` | 모범답안에 있는데 사용자 답에 없는 것 | ○ | ○ |
| `wrong` | 사실이 틀린 것 (수치·인과·용어) | ○ | ○ |
| `overclaim` | 실제 참여 수준을 넘겨 말한 것 | ○ | ○ |
| `style` | 말투·길이·문장이 끊기는 자리 | ○ | **끔** |

**점수를 안 내는 이유를 사용자에게 말한다** — 같은 답을 두 번 채점하면 다른 점수가 나오는데,
그 흔들림을 실력 변화로 읽게 된다. 이 저장소가 *「재는 방법이 없으면 수치를 안 낸다」*를
되풀이해 온 자리와 같다. 정답률·진도 %도 같은 이유로 안 낸다.

**쓰기 모드에서 `style` 을 끄고, 껐다고 한 줄로 밝힌다.**

> 말로 할 때 어떻게 들리는지는 구술 모드에서 봅니다.

### 채점 규칙은 지어내지 않는다

`~/Documents/면접준비/_이어서작업.md` 4절에 여섯 개가 이미 있다. 갈라 쓴다.

**모드와 무관하게 늘 보는 것** — 내용 규칙 넷

1. **표준 용어는 표준 정의로 먼저 설명했나.** 자기 프로젝트 규칙으로 정의하면 지적
2. **이 저장소에서만 통하는 이름을 그대로 인용하지 않았나.** 그 규칙이 하는 일을 문장으로
   말해야 한다. **규칙 1과 헷갈리면 안 된다** — `SO_REUSEADDR`·`GROUP BY` 같은 **표준
   용어는 이름과 뜻을 함께 말하는 것이 맞다**(노트가 2026-09-04 에 실제로 이 혼동을 겪고
   이름을 되넣었다)
3. **지시어를 구체적인 이름으로 말했나.** "세 층", "그 규칙" 은 지적
4. **수치 앞에 그게 왜 문제인지가 나왔나.** 면접관은 746개가 많은 수인지 모른다

**`style` 칸으로 가는 것** — 구술에서만

- 답변 구조: 표준 정의 → 내 프로젝트 상황 → 무엇을 했나 → **안 그랬으면 무슨 일이 났나**.
  마지막이 제일 중요하다. 그게 있어야 직접 부딪혀 본 사람으로 들린다
- 길이: 주 답변 2~3문단(소리 내어 40~60초) · 꼬리답 3~5문장
- 소리 내어 읽었을 때 끊기지 않나

**양쪽 다 안 보는 것** — 겹낫표와 긴 대시. 글로 쓸 때의 규칙이라 말할 때는 해당이 없다.

### `overclaim` 이 넷 중 제일 중요하다

같은 파일 6절이 **사용자의 실제 참여 수준은 「중간」**이라고 못 박아 뒀다. 큰 방향은 본인이
정했고, 세부 설계는 에이전트가 많이 했고, 코드를 전부 읽지는 않았다.

사용자가 그 선을 넘겨 답하면(전부 직접 설계한 것처럼 · 코드를 다 읽은 것처럼) **반드시
짚는다.** 면접에서 제일 크게 다치는 자리다 — 그렇게 답하면 다음 질문이 «그럼 이 파일 지금
설명해 보실래요» 가 된다. **모드를 안 탄다.**

## 4단계 — 저장소에서 만든 질문은 기본이 아니다

사용자가 청할 때만 낸다("저장소에서도 내줘" · "노트에 없는 걸로"). 그때의 규칙:

- 근거는 `CLAUDE.md` 의 함정 절 또는 `.claude/wiki/knowledge/*.md` 의 **문장을 그대로
  인용**한다
- **근거 문장을 못 찾으면 그 질문을 안 낸다.** 모델이 정답을 지어내고 그것으로 채점하면
  채점자가 자기가 만든 답으로 채점하는 꼴이 된다 — 이 저장소가 *"죽은 판정자가 만점을
  받는다"* 로 여러 번 경계한 모양이다
- **노트 질문과 갈라 표시한다.** 모범답안이 없다는 것을 사용자가 알아야 채점을 곧이곧대로
  안 받는다. 기록도 `--kind repo` 로 남긴다

## 5단계 — 한 문항이 끝나면 기록한다

```bash
python "${CLAUDE_PROJECT_DIR}/.claude/harness/scripts/quiz/log.py" --id <id> --mode write \
  --missed "폴백이 걸린 것과 원래 없던 것을 가르는 이유" \
  --wrong "51.8초를 42.3초로 말함" --followups 1
```

**손으로 JSON 을 쓰지 않는다.** `--mode` 에 기본값이 없어 빠뜨리면 죽고, 쓰기 모드에
`--style` 을 주면 거절하고, 지적이 없어도 칸을 빈 목록으로 채운다. 그 셋이 다 **어겨도
에러가 안 나고 파일만 조용히 거짓이 되는** 규칙이라 도구가 지킨다.

지적이 하나도 없으면 목록 인자 없이 부른다.

## 회차를 닫을 때

**표 하나로 요약한다** — 문항 · 단원 · 짚은 것의 수. 점수도 합계도 안 낸다.

그리고 다음에 무엇을 하면 되는지 한 줄로 준다.

> 지난 회차에 걸린 것만 다시 보시려면 `--weak` 로 부르시면 됩니다.

## 이 스킬의 범위

**노트를 안 고친다.** `면접노트.html`·마크다운·`_html2md.py` 는 읽기만 한다. 내용을 고치고
싶다는 말이 나오면 그것은 이 스킬이 아니라 노트 작업이고, `~/Documents/면접준비/_이어서작업.md`
가 그 절차를 갖고 있다.

**아티팩트를 안 만든다.** 이 스킬의 값어치는 대조와 지적인데 정적 페이지는 서술형 답을
채점할 수 없다.

`-m integration` 을 절대 안 돌린다. 이 스킬에 유료 호출은 없다.
