# history-significance

History는 작업 일지가 아니다. Git은 무엇이 바뀌었는지 보존하고 Tests/CI는 현재 동작을
검증한다. 이 스킬은 미래 작업자가 **왜** 그렇게 되었는지를 알아야 할 때만 기록을 남긴다.

## 판단 질문

> 이 정보가 미래 작업자가 중요한 결정, 계획과의 이탈, 실패, 제약 또는 의미 있는 측정을
> 이해하는 데 실질적으로 도움이 되는가?

다음 중 하나라도 해당하면 Significant 후보이다.

- 중요한 아키텍처나 계약 결정
- 여러 대안 중 하나를 고르고 나머지를 기각한 이유
- 계획과 실제 구현이 의미 있게 달라진 일
- 반복할 가능성이 있는 실패와 예상하기 어려운 원인
- 코드만으로 드러나지 않는 운영·호환·비용 제약
- 새로운 baseline, 중요한 회귀, 의미 있는 품질·성능·비용 변화

다음만 있다면 Not Significant다.

- 계획대로 끝난 일반 구현, 파일 추가·이름 변경·포맷팅·사소한 리팩터링
- 일반적인 테스트 추가와 단순 테스트 성공
- Git diff와 테스트 출력으로 충분히 복원 가능한 사실
- 이미 Knowledge나 History에 같은 이유가 있는 반복

애매하면 기록하지 않는 쪽을 기본값으로 한다.

## 기록할 때

가장 알맞은 스킬 하나를 호출한다.

- 구현 전 중요한 결정 → `plan-log`
- 구현 중 계획과 달라진 결정·실패·제약 → `task-log`
- 미래 비교 가치가 있는 측정·회귀 → `verify-log`

History에서 확정된 내용이 현재 시스템의 계약이 되면 관련
`.claude/wiki/knowledge/` 문서에는 **현재 유효한 규칙만** 반영한다. 이유와 기각한
대안은 History에 남기며, 같은 문장을 두 곳에 복제하지 않는다.
