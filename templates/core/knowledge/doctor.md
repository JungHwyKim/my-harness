# Doctor 정적 진단 계약

`python .claude/harness/scripts/doctor.py`는 이 프로젝트에 설치된 하네스의 **공유 설정**을
정적으로 점검한다. 실행 방법과 설치 직후 절차는 `HARNESS-INSTALL.md`에 있고, 이 문서는
그 판정이 **무엇을 근거로 하고 무엇을 보지 않는지**를 둔다.

## 이 명령이 존재하는 이유

설정 오류는 **에러 없이 통과한다.** 세 자리가 특히 그렇다.

- 설정 파일의 읽기·파싱 실패가 빈 사전으로 흡수된다. 설정이 통째로 없는 것과 같아지는데
  아무도 모른다.
- `schema_version`에 `"2"`나 `2.0`처럼 정수가 아닌 값을 적으면 V2 분기가 **꺼진 채로** 돈다.
- 추적 경로 항목에서 끝의 `/`가 빠지면 소비자가 「정확한 파일 하나」로 읽는다.
  `tracked_paths: ["tests"]`는 그 디렉터리 아래 어떤 변경도 잡지 못한다.

세 경우 모두 검사가 꺼진 채로 통과한다. Doctor는 그 조용한 자리만 모아 본다.

## 보장하지 않는 것

**명령을 실행하지 않는 것이 보안·비용 경계다.** 훅·stage·Git·다른 인터프리터를 돌리지
않고, 이 프로젝트의 Python 모듈이나 pytest 설정을 import하지 않는다. 파일·세션 마커·
캐시를 만들지 않고 외부를 호출하지 않는다.

| 보지 않는 것 | 이유 |
|---|---|
| 명령의 실행 성공 | 실행하지 않는다. 결선 PASS는 「연결이 있다」까지다 |
| `pytest`·`ruff` 설치 상태와 버전 | 실행하지 않으므로 미검증이다 |
| 사용자·로컬·관리자 설정 | 공유 파일만 본다. 병합 결과와 활성 상태는 모른다 |
| 실제 세션의 훅 활성 여부 | 설정 파일이 세션 보호를 뜻하지 않는다 |
| 유료 테스트 정책·승인 | `paid-test-approval.md`가 소유한다 |
| 디렉터리 전체의 매핑 커버리지 | 확정 가능한 파일만 본다. 하위 전수 탐색은 하지 않는다 |

`.agents/`와 `.codex/`는 로컬 전용이라 검사하지 않고 부재를 실패로 보지 않는다.

## 대상 루트

`<프로젝트>/.claude/harness/scripts/doctor.py`에 설치해 쓰는 **저장소 로컬 CLI**다.
자기 파일 경로의 상위 세 칸이 `scripts`·`harness`·`.claude`인지 먼저 보고, 맞을 때만 그
위를 루트로 쓴다. 어긋나면 진단을 시작하지 않고 종료 코드 2를 반환한다. cwd나
`CLAUDE_PROJECT_DIR`가 다른 곳을 가리켜도 루트는 바뀌지 않는다.

**훅의 루트 결정과 반대이고, 그것이 의도다.** 그래서 인터프리터 선택도 Doctor의 루트
기준이며, 중첩 프로젝트에서는 실제 훅이 고를 인터프리터와 갈릴 수 있다. 출력이 그 사실을
함께 적는다. Doctor는 실제 훅이 고를 인터프리터를 관찰한 것이 아니다.

## 종료 코드

| 코드 | 조건 |
|---|---|
| 0 | 진단을 마쳤고 FAIL이 없다. WARN만 있어도 0이다 |
| 1 | 진단을 마쳤고 FAIL이 하나 이상이다 |
| 2 | **진단을 못 마쳤다** — 배치 오류, 루트 접근 불가, 예상하지 못한 내부 오류 |

2가 0/1보다 우선한다. 필수 파일 누락과 JSON 오류는 정상 진단의 FAIL이므로 1이다.
Python이 시작조차 못 한 경우의 종료 코드는 이 CLI가 통제하지 않는다.

**미검사는 PASS가 아니다.** 선행 오류로 못 본 검사는 `[WARN] 미검사`로 나온다. 없는 선택
파일과 비활성 설정도 PASS로 꾸미지 않는다.

## 설치 직후의 WARN은 정상이다

기본 설치의 `fast`·`full` Profile은 `triggers`와 `stages`가 비어 있다. 스키마가 허용하는
상태이므로 Doctor는 이를 **FAIL이 아니라 WARN**으로 적고 종료 코드 0으로 마친다.
같은 이유로 추적 경로·매핑·유료 마커가 비어 있는 것도 FAIL이 아니다.

**그 0을 「검사가 통과했다」로 읽지 않는다.** 아직 돌릴 검사가 없다는 뜻이다. Profile을
구성하면 그 WARN이 사라지고, 그때부터 Doctor는 트리거·stage·매핑의 결선을 본다.
활성화 절차는 `HARNESS-INSTALL.md`가 소유한다.
